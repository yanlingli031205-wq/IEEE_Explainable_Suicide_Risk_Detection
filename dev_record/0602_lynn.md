好问题，这正好是该在动手前理清的架构。我分两层讲：**任务要不要分开写**，和**三个模型要在哪些任务上跑**。

## 一、三个子任务要分开写吗？——1a 和 task2 分开，1b 看你选哪条路线

先说结论：**1a 和 task2 必须分开写**，1b 是另一回事（下面单独说）。原因是这三个任务的"输出形态"根本不同，模型的最后一层和损失函数都不一样：

| | task 1a 风险分类 | task 1b 证据抽取 | task 2 因子识别 |
|---|---|---|---|
| 输出 | 4 类选 1（单标签） | 从原文抠文字片段（span） | 24 类各判有无（多标签） |
| 最后一层 | softmax，4 个输出 | 每个 token 标 B/I/O，或 LLM 抽 | sigmoid，24 个独立输出 |
| 损失函数 | 交叉熵（或 ordinal） | token 分类损失 | BCE（二元交叉熵） |
| 评测 | Weighted F1 | Phrase F1 | Macro F1 |

你看最后一层和损失函数三者全不一样，所以**没法用一份训练代码套三个任务**，得分开写训练脚本。

不过有个**省力的关键点**：虽然训练脚本分开，但它们**共用同一套"地基"**——同一份 `train_clean.csv`、同一套 fold 划分、同一套 OOF 评测框架、同一个加载模型的函数。所以不是"从零写三遍"，而是"地基写一次，三个任务各自接不同的头和损失"。这也是为什么我们先把预处理和 fold 做扎实——它是三个任务共享的。

## 二、1a 和 task2:三个模型要分开跑吗?——是的,但不是"三选一",是为了之后融合

是的,**1a 上两个模型（DepRoBERTa-large / DeBERTa-v3-large）分开各跑一遍 5-fold,task2 上同样两个模型分开各跑一遍**（注:本文写作时还是三模型设想,之后 BERTweet 因 max_len=128 丢失长帖证据被移除,见技术报告启动文档"模型选型演化"）。但要理解**为什么**要跑多遍——不是为了挑一个最强的就完事,而是因为:

1. **先比单模型**:三个模型各自的 OOF 分数,看谁强。
2. **再判互补**:看它们错的样本重不重叠(混淆矩阵)。错得不一样 = 互补 = 融合能涨;错得一样 = 冗余 = 选强的那个。
3. **可能融合**:如果互补,在概率层加权平均三个模型的输出。

这套"跑多个 → 判互补 → 融合"的流程,在 **1a 和 task2 上都要做一遍**(它们都是分类任务,都能融合)。所以 1a 跑 3 个模型、task2 也跑 3 个模型,这是值得的——榜单已经证明 task2 是胜负手,在 task2 上多模型融合很可能就是拉开差距的地方。

## 三、1b 不一样,先别急着上三个模型

1b（证据抽取）是这里**最特殊**的一个,我建议你**先不要套"三个模型分开跑"这个思路**,原因有两个:

**第一,1b 可能根本不用"训三个模型"这条路。** 官方明确允许 LLM,而**证据抽取这件事 LLM 特别擅长**(给它原文 + 风险判断,让它划出支撑句)。所以 1b 有两条完全不同的路线:

- **路线 A(微调 token 分类)**:把抽取当成给每个词标 B/I/O,这才需要"训模型"。这条路确实可以上 MentalRoBERTa 等做 token 分类,但**它和 1a/task2 的模型用法不同**(1a/task2 是整句分一个类,1b 是每个词标一个标签),代码差异更大。
- **路线 B(LLM 抽取)**:直接用 LLM few-shot,不训练,写 prompt 就行。

**第二,1b 该不该投入、投到什么程度,取决于性价比。** 1b 占 30%,但 Phrase F1 那套规则(包含/被包含、长度≤3倍、precision/recall 都要顾)很难做高。我的建议是:**1a 和 task2 先落地,1b 先用 LLM 快速试一版路线 B 拿个 baseline**,看能到多少分,再决定要不要投入做路线 A 的微调。别一上来就在 1b 上铺三个模型——可能不划算。

## 落到执行上,我建议的写代码顺序

```
第 1 步:写共享地基(数据加载 + fold + OOF 评测 + 模型加载函数)  ← 写一次,三任务共用
第 2 步:写 task 1a 训练框架 → 三个模型各跑 5-fold → 比较 + 判互补
第 3 步:写 task 2 训练框架(改成 24 头 sigmoid + BCE)→ 三个模型各跑
第 4 步:1b 先用 LLM 试路线 B → 看分数再决定要不要做路线 A
```

第 1 步的地基是关键,它让第 2、3 步不用重复造轮子——加载模型、切 fold、算 OOF 这些逻辑只写一遍,task 1a 和 task 2 只是换最后一层和损失函数。
